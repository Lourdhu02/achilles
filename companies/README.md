# Companies: how to get into the labs that build frontier AI

One guide per organization: where core-AI engineers actually work there, what the hiring process tests, the papers to read, portfolio projects that would impress that team, and a plan to get there. Each guide links back into the labs and tracks in this repo, so preparation is concrete.

> [!IMPORTANT]
> Team names, hiring processes, offices and programs change often. Every guide dates its volatile facts, and each folder has an `agent-brief.md` you can hand to a research agent (or work through yourself) each quarter to refresh them. Verify on the company's own careers pages before you act.

## How to use these guides

1. **Pick two targets, not ten.** Read both guides end to end, then choose the projects that overlap. A kernel project, for example, serves NVIDIA and any inference team; an interpretability project serves Anthropic and research-heavy teams everywhere.
2. **Map the guide to your labs.** Each guide says which labs and curriculum modules its interviews lean on. Finish those first, and turn one into a public write-up.
3. **Build the signal they look for.** The "signals" section of each guide is ranked. Work down it in order, starting with what you can ship in the next 30 days.
4. **Prepare the loop.** Use the [research-engineer track](../tracks/research-engineer/README.md) for coding, system design and the question bank, and [career/stories.md](../career/stories.md) for behavioral and values rounds.
5. **Refresh quarterly.** Re-run each folder's `agent-brief.md` and update anything that changed.

> [!TIP]
> Before applying anywhere, have three things you can link: a lab you implemented and measured, a write-up with error bars, and one contribution to an open-source project the target team uses. That combination separates you from most applicants at every organization listed here.
